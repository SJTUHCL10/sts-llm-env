# 机制覆盖：协议 v5

此表描述当前协议可表达且已接入原生命令的机制。Core 测试验证结构与执行语义，GameSmoke 验证游戏 v0.111.0 的模型/API、升级和序列化契约；实际战斗与 UI 仍需按 VALIDATION.md 验收。

## 角色机制

| 机制族 | 当前支持 | 尚未提供的代表能力 |
| --- | --- | --- |
| 亡灵：奥斯提 | summon，Osty 单体/群体攻击、治疗/失去生命、按生命/最大生命/格挡计算与条件 | 专门的“奥斯提本回合已攻击”统计、复活/牺牲专用动作 |
| 亡灵：灵魂 | 固定生成、按 ID 选择/移动/消耗/复制/升级，消耗灵魂触发规则 | 历史消耗灵魂数量直接作为数值变量 |
| 亡灵：灾厄 | 原生 doom；按当前层数、生命和伤害表达式增加层数，使用原生灾厄结算 | 复制任意 debuff、改写灾厄结算时机、独立处决动作 |
| 机器人：充能球 | 闪电/冰霜/黑暗/等离子/玻璃/随机球；首球/末球/全部激发，可保留；被动触发；球槽增减；球数/槽位表达式与球事件 | 按球类型筛选、任意中间位置指定球、调整单个球存储数值 |
| 机器人：集中与状态 | 正负集中、暂时集中；伤口/晕眩/灼伤/虚空/黏液/燃料；筛选状态牌消耗/变化；随机/发现能力牌及自动打出 | 单牌永久成长、任意原生能力的完整复刻 |
| 储君：星 | gain_stars、固定或 X 星费用、剩余星/实付星表达式、机制升级改变星费用 | 本回合星收入/支出专属计数与星变动事件 |
| 储君：铸造与衍生牌 | 原生 forge、君王之剑、碎屑/仆从、生成/发现无色牌、生成卡牌事件 | 单独定制君王之剑规则、变化目标为任意未登记固定牌 |
| 静默：小刀与奇巧 | 小刀生成、指定小刀操作/出牌事件；Sly；原生批量弃牌；临时赋予奇巧 | 区分手动打出与奇巧打出的专门事件 |
| 静默：中毒 | 正常毒、读毒层数/条件、按现有毒倍增增量、毒相关普通事件规则 | 立即额外结算毒、任意专用毒能力 |
| 共享：生命、格挡与状态 | heal/lose_hp、格挡、正负力量/敏捷、暂时力量、虚弱/易伤/脆弱/活力/反伤/覆甲/无实体/人工制品/缓冲/格挡保留 | 增加最大生命、直接设置格挡、任意临时状态与规则改写 |

原生状态的附带行为交给游戏处理：灾厄阈值、集中对球数值的影响、充能溢出激发、奇巧弃牌后打出及铸造产生/强化君王之剑均沿用原生实现。

## 共享表达能力

| 能力 | 实现 |
| --- | --- |
| 升级机制 | 两个完整形态，费用/关键词/动作/规则可独立改变 |
| 卡牌操作 | discard/exhaust/move/select/upgrade/copy/transform/create_card/play/关键词与费用修改 |
| 通用选择 | hand/draw/discard/exhaust × random/choose/all/first/last × ID/类型/稀有度/当前费用/升级/关键词筛选 |
| 来源 | 固定登记别名；角色/无色卡池随机生成或发现；可升级生成牌 |
| 连续操作同一张牌 | select + selected:名称，不反复随机抽取 |
| 动态数值 | stat/add/mul/div；即时读取状态、实付 X 资源、事件数值、最近伤害 |
| 条件 | 比较与 all/any/not，可按每个目标检查 |
| 事件规则 | 12 类事件、规则组、回合/战斗额度、匹配事件序号、有限与整场持续 |
| 运行保护 | 递归重入保护、触发深度及操作数量保护，不实施数值平衡预算 |

固定生成别名由 MechanicCatalog/NativeMechanics 共同维护；当前共 13 个。这让定向生成和定向筛选使用同一标识，而无需把游戏中所有卡牌或任意模型类名塞进协议。其他原生牌可以通过卡池 random/choose 和筛选生成；尚不能按任意原生卡 ID 定向生成。

## 角色可用性

四种扩展按原生角色/卡池 ID 判断。棱彩宝石 PRISMATIC_GEM 开放所有已实现扩展；牌组中已有对应原生卡池也开放扩展。生成牌不能自我解锁。校验遍历两个形态、规则、筛选及嵌套表达式，避免从升级或条件引用绕过范围。

共享操作不按角色优势设为独占；扩展可选，不附加定价、生成权重或强制主题。LLM 看到原生卡说明也只能组合已实现机制。

## 后续边界

不提供战斗外永久成长、任意附魔/负面属性写入、任意原生能力类、生命周期拦截/替换、联机定义同步。不同卡牌独有规则应先确认可拆为现有动作或原生状态，再新增复用能力，避免添加以单张卡命名的特殊字段。

参考 AutoAnthony 的组件目录时，区分“原生参考记录”和“可执行契约”；其定价、频率与完整规则系统不直接移植。项目仍保持 Core BCL-only，游戏侧有明确原生适配器。
