核对日期：2026-10-04。基于当前工作区（包括已有未提交修改）、已安装 v0.111.0 游戏与本机 AutoAnthony 源码；这是一份机制族对照，不是逐个组件等价证明。

## 当前可执行范围

- 13 种效果：伤害、格挡、抽牌、能量、力量、敏捷、虚弱、易伤、中毒、随机弃其他手牌、随机消耗其他手牌、随机弃牌回手、星。
- 9 种时机：打出时、下回合开始、每回合开始/结束、打牌/攻击/技能/抽牌/消耗事件。
- 4 种目标：自身、选定敌人、所有敌人、随机敌人。
- 条件：有格挡、生命低于一半、目标虚弱/易伤；缩放：格挡、手牌/弃牌/消耗堆数量、目标中毒、自身星。
- 关键词：消耗、虚无、保留、固有；固定能量/星费用与升级减费；有限/整场能力持续时间与事件次数限制。

力量、敏捷、虚弱、易伤、抽弃、消耗、保留、能力牌、零费和高费不适合全部划为角色独占。AutoAnthony 的各角色原生目录也含共享操作；例如扣血出现在铁甲、静默和亡灵目录中。`notes/characters.md` 的“优势”适合作为设计观察，不能直接变成硬性权限或必选主题。

## 与 AutoAnthony 的主要差距

## 已落实的角色范围修正

共同协议移除中毒；静默追加中毒扩展，储君追加星扩展。原生棱彩宝石 `PRISMATIC_GEM` 开放全部已实现角色扩展；牌组中实际已有的原生静默/储君卡池也开放对应扩展。使用原生模型/卡池 ID，不靠翻译文字，不把生成牌当成解锁证据。原生 ID 已由安装游戏 smoke 检查确认。

PromptBuilder、生成会话、CLI generate 共享 `CharacterMechanics`。生成结果违反范围时整批拒绝；已有候选与保存的牌不追溯删除，结构校验和存档兼容规则保持不变。

亡灵/机器人专有机制尚未加入 DSL；此轮不在 prompt 中提供未实现的机制。角色扩展可选且无默认权重，优势清单不写成偏好指令，原生牌说明只能提供灵感。

## 多样性后续方案

1. 优先补齐亡灵的召唤、奥斯提攻击、灾厄、灵魂；机器人补充生成球、激发、集中、槽位。每个机制同时补结构校验、执行、说明、预览、原生提示框、事件归属、存档和游戏检查。
2. 可用范围和采样分布分离。先通过原生卡池与明确的跨角色来源得到权限；不要用 `notes` 中“优势”人为提高概率。
3. 从原生卡的结构提取角色/稀有度/类型下的机制频率，作为可选软先验。AutoAnthony 的 `NativeComponentFrequencyTracker` 已采用按相关原生卡出现次数形成的来源先验；移植前应合并同义操作，避免把多个 template 当成多个设计主题。
4. 历史比较同时看效果族、功能、费用、时机；轻度抑制最近重复，不硬性要求每张牌包含角色扩展或两三个效果。已有机制指纹去重并不等于分布多样性。
5. 多张奖励时，后续可先分配差异化设计方向（即时收益、持续成长、资源/牌组配合等），再在当前权限里设计。不规定“必须一张职业牌”，不规定固定配比。
6. 用多场离线样本比较加入扩展前后：效果族占比、角色机制占比、费用/类型/时机分布、近重复率、拒绝率与 token 成本。本局一次一张的 43 次成功结果只能发现倾向，不能据此设死比例；LLM 接收到“可选”也不能保证分布不变。

允许角色机制后是否过度集中，需用实测分布回答。默认先实行权限隔离与简短的多样性指令，再根据历史做温和纠偏；不立即增加硬配额、频率权重或独立规划请求。
