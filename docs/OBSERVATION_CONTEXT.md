# Observation context

`OBSERVATION_JSON` is a design view, separate from persisted game captures and the executable card protocol.

- `hp` / `max_hp` live beside `character` and `gold`. Current run health takes precedence; older captures fall back to player/state health. `combat.player` retains block and powers, without identity or health duplication.
- `combat.stars` and `combat.orb_capacity` follow `CharacterMechanics.FromRun`: Regent/Defect respectively, native cards from their pools, or Prismatic Gem. Enabled resources remain present even at zero; unavailable fields are omitted.
- `combat.summary.cards_played` uses `name`, lowercase `type`, `origin`, and `count`, without an ID. Count sums player `CardPlayFinishedEntry` events over the whole combat, keyed internally by card model ID and displayed title. Nonconsecutive plays merge; this is neither play order nor number of copies in the deck. Distinct instances with the same ID/title merge. Upgrades only separate if their displayed title differs.
- `deck[].enchantment` retains `id` and `amount`, and adds `text` from native `DynamicDescription`, formatted using current amount/variables and stripped of display markup. If localization fails, no text is invented. Older captures without descriptions remain readable.

## Power IDs

Observation power IDs come directly from `PowerModel.Id.Entry`. They are native model identifiers, not a closed protocol enum; mods can introduce additional powers. Keep these identifiers intact to avoid conflating unrelated native effects.

The executable card protocol supports this subset through explicit aliases in `NativeMechanics.Power`:

| Protocol alias | Observation ID |
| --- | --- |
| `strength` | `STRENGTH_POWER` |
| `dexterity` | `DEXTERITY_POWER` |
| `weak` | `WEAK_POWER` |
| `vulnerable` | `VULNERABLE_POWER` |
| `frail` | `FRAIL_POWER` |
| `poison` | `POISON_POWER` |
| `doom` | `DOOM_POWER` |
| `focus` | `FOCUS_POWER` |
| `vigor` | `VIGOR_POWER` |
| `thorns` | `THORNS_POWER` |
| `plating` | `PLATING_POWER` |
| `intangible` | `INTANGIBLE_POWER` |
| `artifact` | `ARTIFACT_POWER` |
| `buffer` | `BUFFER_POWER` |

Other observed powers are not automatically executable by generated cards. Temporary strength/focus also use native cleanup powers (`FLEX_POTION_POWER`, `DARK_SHACKLES_POWER`, `HOTFIX_POWER`, `HYPERBEAM_FOCUS_DOWN_POWER`); those are not additional protocol aliases.
